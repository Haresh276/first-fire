# How to evaluate FIRST FIRE

**Question.** Can a reader find a defensible answer to a new spacecraft-fire question, locate the supporting primary evidence, and state the condition that limits its use, within the same time as ordinary web search? The dashboard’s public worked cases are practice. Internal software checks and six scripted demonstrations supply no human performance measurements.

## A practical six-case pilot

1. Freeze the site, dated public sources, and search policy. Have an independent assessor write six unpublished prompts after that freeze, ideally two direct findings, two conditions that change the conclusion, and two plausible questions with insufficient evidence. Use different investigations and materials; avoid sentence fragments copied from the guide, project headlines, and questions that can be answered by matching a panel title. Test for reasonable searchability in the comparison environment. For each prompt prewrite a supported decision, accepted evidence locations/alternatives, a scope boundary, and acceptable abstentions. Date both files; an external evaluator can timestamp their hashes without sharing any answers.
2. Use the local files in **evaluation-examples/** to rehearse format and scoring. They include six public-domain research topics and attributable primary sources. They have been viewed by the implementation team; even if kept outside the deployed website, they **are not independent holdouts**. The example identifier is automatically treated as practice. For a real study the assessor creates two new files on their own device. The participant JSON contains only version, study_id, time_limit_s, and six {id,prompt} entries. The matching key contains version, study_id, and six {id,accepted,evidence,limit,sources:[URL]} entries. Give the participant only the first file. Source links and cue words belong in the key. An evaluator can load it in a locally served checked release on a separate, offline machine. Never commit real private files to the project, public source repository, public Pages or build logs; exclusions in a static build do not protect files committed to a public repository. Browser file selectors are local import, not identity or access control.
3. Recruit readers resembling the intended audience, record the mix of scientific/search experience in aggregate, and exclude people who wrote the cases or know the keys. Offer equal familiarization in both tools using unrelated examples. Use the same device, browser, external search access, primary-source criterion, and four-minute cap per case. Keep the tool and ordinary search open in separate tabs. Ordinary search may use normal query reformulation, web/PSI/NTRS search, and full-text PDF search. Block or explicitly exclude the team's site and its mirrors **only in the ordinary-search condition**. Specify whether search-engine AI overviews are enabled, apply a predeclared policy consistently, log deviations, and avoid ad hoc assistance or citation hints. This comparison measures the whole tool and its curation. A separate same-corpus keyword/PDF arm tests navigation alone.
4. The facilitator assigns a random participant to an unused anonymous slot. The 12 slots rotate case order across six positions, switching the starting method for each matched slot pair. Every reader sees every case only once and three cases per method. Across a full block of twelve, each case occupies each position once per arm. For a six-reader feasibility pilot, randomly select three distinct slot pairs (e.g. 1/2, 5/6, 9/10) and shuffle participant assignment. Each case then appears three times per method, but order/learning differences are only partly balanced. Each person should complete 6 × 4 minutes maximum plus instructions and breaks. Obtain consent for deidentified local recording, let participants stop; record enrolment, nonreturn and dropout counts separately. Do not treat 36 responses as 36 independent users.
5. In the Participant tab, load the facilitator pack and the assigned slot. Start each case only when the participant is ready; the clock runs when the prompt is revealed. The session captures the last entered answer, source, and scope at the deadline. Reloading respects the original deadline even if a tab was closed. No timer runs between tasks. Keep exactly one active study tab; browser storage is per-device, and clearing it removes the local session. Timeouts count toward the full denominator, with their actual submitted content scored. The app cannot enforce which search tools people use. Monitor according to a shared agreement; log exceptions without collecting search histories unless consent covers that.
6. Export the **masked responses** for independent assessment and the **analyst record** for the facilitator. The latter contains the method, order and time. A random response ID links the files, the masked responses omit that metadata, and response order is shuffled by ID. Do not give the grader the analyst files; if an answer names the tool, a facilitator can redact only the tool name using a predeclared rule while retaining source URLs and meaning. Users see their assigned interface, so describe this as *assessor-masked*, not a double-blind trial. A grader may still recognize wording.
7. Each assessor imports the key and a masked response file on a separate device. Score one point each for the decision, a primary source and usable locator supporting it, and a meaningful scope limitation. Permit equivalently supported answers/locators. If a primary source contradicts the frozen key, adjudicate the case for both methods, document it, and repeat the comparison transparently. A URL to the site home page or a quote that fails to entail the decision does not earn the evidence point. For an insufficient-evidence item, credit a justified boundary and the closest evidence showing what was actually tested. A bare “unknown” earns no automatic evidence point. Include a predeclared answer that would overstate safety for each such case; count these separately by manual review if present. Have two masked graders score all six cases independently for a small pilot, report raw per-criterion agreement, and adjudicate discrepancies before accepting one final grade file per response.
8. In Analyst, import completed analyst records and adjudicated grades together. The summary gives full-credit count, criterion counts, timeouts, median elapsed time (timeouts included) and a within-reader comparison (difference out of three per method), with results by task and an export by anonymous run and case. Missing or duplicate grades, mismatched case text/time limits and practice records are rejected. Partial analyst exports let the facilitator document withdrawals, but the main app summary is explicitly for completed runs; report all assigned cases and missing cases separately, plus a sensitivity calculation treating unattempted tasks as incorrect. Report time and evidence accuracy side by side, plus the exact denominator. A one-minute wrong answer is not better than a two-minute well-supported one.

## Analysis choices in order of priority

| Rank | Candidate | What could go wrong | Acceptance test |
| --- | --- | --- | --- |
| 1 | Matched, randomized, assessor-masked comparison against normal search | Prompts leak into the dashboard or scoring exposes the method | Independent post-freeze prompts and key, equal resources/time, an auditor can account for every assigned response. |
| 2 | Criterion-level evidence and scope scoring | A similar phrase gets credit without a supporting source | Two blinded readers can locate the evidence. Test a reversed conclusion with a real citation and permit alternative equivalent sources. |
| 3 | Purposeful comparison including insufficient evidence | An always-abstain strategy looks accurate | Count both valid supported decisions and false assertions. Check a positive and negative case with matched terminology. |
| 4 | Same-corpus search comparison | Excludes advantages of ordinary search and answers a narrower question | Run and label it separately. Provide full-text PDFs and keyword search to the comparison arm. |
| 5 | Time-to-answer comparison | Fast unsupported answers win; survivor bias from discarding timeouts | Show full-credit rates and all timeouts beside timing. If reporting correct-only time, label its selected denominator. |
| 6 | Automatic agreement with example answers | Wording and project-team knowledge contaminate the test | Use for dry runs only; no claim about real people, independent evidence or safety. |

With six participants, report each reader’s and each case’s results. Descriptively report the paired difference in full-credit count per reader (each method out of three); a difference of one answer changes a reader's rate by 33 percentage points. An uncertainty analysis can randomize the arm labels **within the actual matched assignment pairs** and enumerate the eight possible arm swaps for three pairs, holding cases/order fixed. This test has little resolution; the smallest attainable one-sided p is 1/8. Do not run a naïve binomial test on the 36 cells. Twelve slots improve balance but still use only six hand-picked case types. A larger independent pilot should reserve new case families and people, set a target practical effect and required sample size prospectively, and resample both readers and cases for generalization. Reports need the run count, method policy, freeze, missingness, agreement, and adverse findings beside any headline result.

## Smoke-detection case design review

The SAME and SAME-R campaigns heated spacecraft materials below ignition aboard the ISS. The first flight used a DBP-loaded wick; Pyrell replaced it on the reflight. The 2018 paper's results section describes more than 100 samples over six materials across the experiments, while the abstract and popular five-material summary focus on representative smoke-producing materials. That total is not the number of usable Teflon or paired-detector observations. On the graph, the ionization instrument's offset from baseline and scaled A/D values should be interpreted against its own threshold; comparing absolute voltages between detectors is invalid. The Shuttle detector ran intermittently because its pump consumed aerosol needed for aging tests. [NASA reflight record](https://psi.nasa.gov/physci/repo/data/investigations/PSI-101) · [Meyer et al., §3.2, Figs. 9–10](https://pmc.ncbi.nlm.nih.gov/articles/PMC7918997/) · [NIST account](https://www.nist.gov/news-events/news/2018/05/nistnasa-study-shows-one-detector-doesnt-fit-all-smoke-spacecraft)

| Rank | Design | Evidence against or limitation | Acceptance test |
| --- | --- | --- | --- |
| 1 | Explain a material-specific threshold crossing using Fig. 9 | The paper provides material-specific fractions; the total test count is not the denominator | Preserve the authors’ two-thirds for Teflon and over half for Kapton, identify the ISS light-scattering detector, and never translate those to population miss rates. |
| 2 | Join experiment condition to specimen image and source | A single microscopy image does not identify the detector response | PSI-101 test 56 links to unaged Teflon in Fig. 10(a); keep the row's 8.1 cm/s inlet speed and 60 s heating separate from any individual alarm verdict. |
| 3 | Compare instrument physics under the same material heading | ISS optical and Shuttle ionization measurements have different response scales and incomplete pairing | Interpret against each threshold; display unequal coverage; refuse an absolute voltage ranking or an all-material winner. |
| 4 | Contrast a strong response with a weak response | Signal saturation obscures relative signal amplitude; it says nothing about worst-case alarm delay | Identify silicone rubber, Pyrell or cotton lamp wick as examples of strong ISS signals; leave precise saturated amplitude and unreported detection time unknown. |
| 5 | Evaluate transfer to ground smoke tests | The authors’ equivalent particle-size comparison is tied to matching flow, heating and aging; lower flow may change results | Fig. 8 supports a conditioned comparison at 8.1 cm/s, but it does not certify a new detector or a lunar-habitat installation. |
| 6 | Predict operational misses from material name alone | Design, dust, background, transport, concentration and actual human-rated environment are missing | An alarm-rate question about future lunar fires directs the reader to those missing measurements and yields no numerical probability. |

The authors’ quantities and figure caption support these checks; an exact per-material trial denominator cannot be recovered from the article text alone. Retrieve run-level measurements and inspect flagged, duplicate or overlapping points before offering counts.

## The optional test-budget decision

After the three primary fields each case also asks what to do with one experimental budget. A participant can select reanalysis, a new test, a different material, or another action, and give an evidence-based rationale. Leaving both fields blank skips this secondary endpoint. An incomplete attempt may receive zero. State before collection whether this endpoint is being studied. If so the assessor adds a text field `next_action` to each private *key* row defining what evidence, control, comparison, or missing observation would warrant credit. Multiple reasonable actions may earn credit when justified. No action is preselected.

A grader makes an explicit 0/1 decision for each attempt with a rubric. The three primary criteria remain unchanged. The analyst reports budget decisions supported among graded, attempts among those offered, skipped cases and attempts without a rubric. A record created before this feature has no budget opportunity and is excluded from those denominators. The browser rejects malformed or inconsistent raw/masked/grade files, including a claimed budget grade on a missing opportunity. Review the full distribution of choices in the row export: missing an optional answer is different from a substantively wrong answer. If mixed versions, missing rubrics or differential response occur, disclose the counts. Do not combine the budget score with the three-point primary endpoint.

**Practice has two routes.** The dashboard button uses six public source cases, reveals their published decisions after completion, and stores the run as practice. The two example JSON files in evaluation-examples/ form a separate six-question rehearsal: import the example participant file, finish it, export both outputs, then load the example key and masked file on the Assessor tab. All grades start unselected. Its rubric explains the budget action too. The Analyst intentionally rejects BOTH types of practice. For a genuine study, generate an independent unseen pack and key after the tool freeze, use a new study ID, run with new participants, and import those study records and grades for the two-arm analysis. Renaming rehearsals does not establish independence.

## Keeping a blind case independent

Assign every observation from one physical burn, including ignition, extinction, camera views and derived rows, to the same development or holdout group. For the two study arms, select candidate experiments from their pre-burn conditions. Save that selection before examining the target outcome. An analogue selected because its outcome agrees with the prediction cannot provide an independent test. Record the source IDs, group assignment, selection criteria and time they were fixed alongside the sealed answer key. [Code-review examples](code-review.md)
